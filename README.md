# TermBoost

Research code for **TermBoost: The n-th Coprime-Exclusive Multiple in O(1)**. The
repo implements and benchmarks two ways to find the `n`-th smallest integer
divisible by exactly one of two coprime integers `a`, `b`: an existing
**binary-search approach**, and a **formula-based, O(1) approach** I derived
(`trUE_n_Smallest_AB`).

The full written derivation (with an interactive visual proof you can drive
with sliders) lives on my site:

## Problem statement

Fix two coprime integers `a, b > 1` with `a < b`, and a positive integer `n`.
Find the `n`-th smallest positive integer divisible by `a` or by `b`, but not
both — the symmetric difference of the two multiple-sets, read off in
increasing order.

For `a=2, b=3` the qualifying integers start `2, 3, 4, 8, 9, 10, 14, 15, 16, ...`
— `6` and `12` are skipped, since they're multiples of both.

### Constraints (problem)
- `a`, `b`, `n` are integers.
- `a` and `b` are coprime: `gcd(a, b) = 1`.
- `a`, `b` > 1.
- `n` > 0.
> The driver code enforces `a < b`; the algorithm assumes this too.

### Constraints (benchmarking)
- `2 ≤ a, b ≤ 100,000`, coprime.
- `1 ≤ n ≤ 10,000,000`.
- Test cases mix small (`1 ≤ n ≤ 1,000`), medium (`1,000 ≤ n ≤ 1,000,000`),
  and large (`1,000,000 ≤ n ≤ 10,000,000`) values.

## Approaches implemented

1. **Binary search** (`binaryApproach`) — binary-searches the monotone
   counting function `count(x) = floor(x/a) + floor(x/b) - 2*floor(x/(ab))`
   for the smallest `x` with `count(x) >= n`.
   Complexity: `O(log(range))` floor-division evaluations.

2. **Formula-based** (`trUE_n_Smallest_AB`) — exploits the fact that the
   qualifying integers repeat periodically with period `ab`, with exactly
   `a + b - 2` qualifying terms per period, then solves the position inside
   one period via a continuous relaxation and a single comparison.
   Complexity: `O(1)`.

Both are cross-validated against a brute-force `findNthTerm` in
`Main.isValidResult`.

## Benchmark

Regenerating with this repo's own `TestCaseGenerator` (1,000,000 coprime
pairs, `a, b ∈ [2, 100000]`, `n` mixed across the three bands above) and
running `Main.benchmark`:

| Approach           | Total time | Correct on all 1,000,000 cases |
|---------------------|-----------:|:-------------------------------:|
| Binary search        | ~215 ms    | Yes                             |
| Formula-based, O(1)  | ~19 ms     | Yes                             |

The formula-based approach ran roughly **11x faster** in this environment,
with zero mismatches against the binary-search / brute-force baselines.
(The original exploratory run reported ~20x on different hardware — the
exact multiplier is JIT-warmup- and machine-dependent; the O(1)-vs-O(log n)
gap widens further as `a`, `b`, `n` grow.)

Corroborating runs on the same **200,000** generated cases (0 mismatches):

| Implementation   | Binary search | Formula  | Speedup |
|------------------|--------------:|---------:|--------:|
| C++ (`-O2`)      | 42.82 ms      | 0.45 ms  | ~95x    |
| Python           | 1308.84 ms    | 64.36 ms | ~20x    |

Absolute times are machine-dependent; the O(1)-vs-O(log n) *shape* is the
point (see `proof/figures/` and the C++/pytest cross-checks).

## Usage

### Running the benchmark
```sh
javac -d out src/com/company/Main.java src/com/company/TestCaseGenerator.java
java -cp out com.company.TestCaseGenerator 1000000 src/com/company/test_cases.txt
java -cp out com.company.Main
```

### Running the Python proof
```sh
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 proof/proof.py
```
This prints the symbolic checks, the exact-lemma verification, and the numeric
cross-check to stdout, asserts zero mismatches, and writes four figures to
`proof/figures/`. See [`PROOF.md`](PROOF.md) for the full writeup with the
figures embedded.

### Running the correctness tests
```sh
pip install -r requirements.txt         # includes pytest
PYTHONPATH=src pytest tests/ -q          # exhaustive + random correctness checks
# or standalone:  python3 tests/test_correctness.py
PYTHONPATH=src python3 benchmark.py test_cases.txt   # Python benchmark over src/termboost
```
The lemma/theorem writeup these exercise now lives in the single root
[`PROOF.md`](PROOF.md) (see "Step 3½ — why 'two candidates' is exact").

### Running the C++ benchmark
```sh
cd cpp && g++ -O2 -std=c++17 -o benchmark benchmark.cpp
./benchmark ../test_cases.txt
```
Runs its own brute-force self-test on startup, then verifies and benchmarks
`binarySearch` vs. `formula`.
